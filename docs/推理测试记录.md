# 推理测试记录

## 概述

在部署完成（torch 2.5.1+cu124, CUDA 12.8, RTX5880-Ada-48Q）基础上，继续完成了以下测试：
- LoRA 权重推理（RGB-only）
- Marigold 深度/法线估计 + 自定义图片 RGBDN SFT 推理
- 全部三张测试样本的推理

## 环境变更

由于 `peft>=0.19` 要求 `torchao>=0.16.0`，而 `torchao>=0.17.0` 需要 `torch>=2.11`，最终调整如下：

| 包 | 旧版本 | 新版本 |
|---|---|---|
| torch | 2.5.1+cu124 | 2.6.0+cu124 |
| torchvision | 0.20.1+cu124 | 0.21.0+cu124 |
| torchao | 0.7.0 | 0.16.0 |

注：`torchao 0.16.0` 加载时会报 `Skipping import of cpp extensions due to incompatible torch version` 警告，但功能正常。

## 测试 1：RGB-only LoRA 推理

```bash
python inference/inference_rgb_lora.py \
  --weights_path anyeZHY/tesseract/tesseract_v01e_rgb_lora \
  --image_path asset/images/fruit_vangogh.png \
  --prompt "pick up the apple google robot"
```

- 模型：CogVideoX-5b-I2V（base）+ tesseract_v01e_rgb_lora（LoRA）
- 分辨率：256×320
- Steps：50
- 耗时：5min 47s（~6.96s/step）
- 显存：峰值 35.7GB，分配 22.5GB
- 输出：1 个视频（num_validation_videos=1）
- 输出文件：`results/val_0_pick_up_the_apple_google_robot_0.mp4`（557KB）

代码逻辑（`inference/inference_rgb_lora.py`）：
1. 加载 CogVideoX-5b-I2V 基础 pipeline
2. 从 HuggingFace 下载 LoRA 权重并注入（`load_lora_weights`）
3. 使用 DPMScheduler，50 步去噪生成 49 帧视频

## 测试 2：自定义图片 + Marigold 深度/法线 + RGBDN SFT 推理

完整链路：下载自定义图片 → Marigold 估计深度和法线 → RGBDN SFT 生成视频

### 2.1 下载测试图片

```python
from diffusers.utils import load_image
img = load_image('https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/cat.png')
```

### 2.2 Marigold 深度/法线估计

```bash
python inference/inference_marigold.py --image_folder asset/images/
```

首次运行需下载两个模型（各 ~12 个文件，约 7min/个）：

| 模型 | 大小 | 来源 |
|---|---|---|
| prs-eth/marigold-normals-v1-1 | ~2.1GB | HuggingFace |
| prs-eth/marigold-depth-v1-1 | ~1.8GB | HuggingFace |

生成的文件：
- `asset/images/cat_depth.npy`（2.8MB）
- `asset/images/cat_normal.png`（359KB）

### 2.3 RGBDN SFT 推理

```bash
python inference/inference_rgbdn_sft.py \
  --image_path asset/images/cat.png \
  --prompt "a cat walking on the table"
```

- 模型：CogVideoX-5b-I2V + tesseract_v01e_rgbdn_sft
- 分辨率：480×640
- Steps：50
- 耗时：~8min/视频（~9.6–9.9s/step）
- 显存：峰值 33.3GB，分配 19.9GB
- 输出：2 个视频（num_validation_videos=2）
- 输出文件：
  - `results/val_0_a_cat_walking_on_the_table_0.mp4`（364KB）
  - `results/val_0_a_cat_walking_on_the_table_1.mp4`（366KB）

## 汇总

| 测试 | 输入图片 | 模型类型 | Prompt | 输出 | 单步耗时 | 总耗时 |
|---|---|---|---|---|---|---|
| SFT | fruit_vangogh | RGBDN | pick up the apple google robot | 2 videos | ~9.7s | ~16min |
| LoRA | fruit_vangogh | RGB | pick up the apple google robot | 1 video | ~7.0s | ~5.8min |
| Marigold+SFT | cat.png (custom) | RGBDN | a cat walking on the table | 2 videos | ~9.8s | ~16min |
| SFT | majo.jpg | RGBDN | a person picking up a cup | 2 videos | ~9.7s | ~16min |

显存峰值约 33–36GB（RTX5880-Ada-48Q 48GB 足够）。
SFT（480×640）比 LoRA（256×320）每步慢约 2.7s，分辨率更高。

## 注意事项

1. `peft>=0.19` 要求 `torchao>=0.16.0`，需配合 `torch>=2.6`；`torchao>=0.17` 要求 `torch>=2.11`，不可混用
2. 不同 inference 脚本输出文件名可能冲突（`val_0_pick_up_the_apple_google_robot_0.mp4` 被 LoRA 覆盖了 SFT 的结果）
3. Marigold 模型首次下载较慢（~7min/模型），下载后缓存至 HuggingFace cache
4. Marigold 输出法线为 PNG、深度为 NPY，命名规则 `{image_name}_normal.png` / `{image_name}_depth.npy`
