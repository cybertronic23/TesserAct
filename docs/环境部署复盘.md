## 完整部署流程

### 1. 环境准备

**背景：** 这台服务器没有 conda（`which conda` 无输出），使用 `venv` 替代。系统自带 Python 3.10.12。

**关键命令：**

```bash
# 安装 venv 支持（Ubuntu 22.04 需要额外安装）
sudo apt install python3.10-venv -y

# 创建虚拟环境
python3 -m venv .venv
source .venv/bin/activate

# 升级基础工具
pip install --upgrade pip setuptools wheel

# 安装项目依赖
pip install -r requirements.txt

# 安装项目本身
pip install -e .
```

**注意点：** 系统 apt 源使用了阿里云镜像（`mirrors.cloud.aliyuncs.com`），部分包可能出现 404。先执行 `sudo apt-get update` 刷新源列表再安装。

### 2. 网络问题与解决

#### 2.1 GitHub 远程仓库无法访问

**现象：** `git pull` 报错 host key 不匹配

```
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
Host key for github.com has changed and you have requested strict checking.
Host key verification failed.
fatal: Could not read from remote repository.
```

**排查：** `ssh -v git@github.com` 发现连接到的 IP 是 `[内网代理IP]`

```
debug1: Connecting to github.com [内网代理IP] port 22.
```

确认是内网地址：`nslookup github.com` 返回 `Address: [内网代理IP]`。

**根因：** 云服务商的 DNS 劫持，将外网域名解析到了内网 NAT 代理。

**解决：** 将远程地址从 SSH 切换为 HTTPS

```bash
git remote set-url origin https://github.com/cybertronic23/TesserAct.git
```

验证：

```
origin  https://github.com/cybertronic23/TesserAct.git (fetch)
origin  https://github.com/cybertronic23/TesserAct.git (push)
```

之后 `git pull` 正常：

```
From https://github.com/cybertronic23/TesserAct
   c4fe64b..9a827bc  my-dev     -> origin/my-dev
Updating c4fe64b..9a827bc
Fast-forward
```

#### 2.2 HuggingFace 模型下载极慢

**现象：** 推理脚本卡在 "Fetching 17 files: 0%"，长时间无进展。

**排查：** DNS 同样被劫持

```
$ nslookup huggingface.co
Name:   huggingface.co
Address: [内网代理IP]

$ nslookup cdn-lfs.huggingface.co
Name:   cdn-lfs.huggingface.co
Address: [内网代理IP]
```

测速小文件（受连接建立时间主导）：

```
Speed: 45 bytes/s
```

测试大文件（使用 Range 头，避开连接建立时间）：

```
$ curl -L --max-time 60 -o /dev/null -s -w "Speed: %{speed_download} bytes/s\n" \
  -H "Range: bytes=0-20971520" \
  "https://huggingface.co/THUDM/CogVideoX-5b-I2V/resolve/main/transformer/..."
Speed: 9496878 bytes/s  (~9.5 MB/s)
```

**结论：** 小文件测速有误导性。大文件实际速度 ~5-10 MB/s，通过内网代理直连可用。

#### 2.3 ClashX 代理反而更慢

**现象：** 配了 ClashX 日本节点后速度变慢。

**对比数据：**

```
# 直连（unset proxy）
curl --noproxy "*" -H "Range: bytes=0-20971520" ...
Speed: 9496878 bytes/s  (~9.5 MB/s)

# 走 ClashX 代理
Speed: 1356775 bytes/s  (~1.3 MB/s)
```

**根因：** 服务器本身就在日本 KDDI 网络。ClashX 日本节点反而多绕了一跳，ClashX 客户端在本地（127.0.0.1:7890）做转发，增加了延迟和带宽瓶颈。

**解决：** 下载模型时不走代理

```bash
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY
```

### 3. 依赖兼容性问题

#### 3.1 PyTorch + CUDA 版本不匹配

**现象：** `pip install -r requirements.txt` 安装了最新 PyTorch 2.12.0+cu130，但 CUDA 不可用

```
UserWarning: CUDA initialization: The NVIDIA driver on your system
is too old (found version 12080). Please update your GPU driver by
downloading and installing a new version from the URL: ...
```

**排查：**

```
$ python -c "import torch; print(torch.cuda.is_available())"
False

$ nvidia-smi
NVIDIA-SMI 570.172.18    CUDA Version: 12.8
```

PyTorch 2.12.0+cu130 需要 CUDA 13.0 runtime，而系统驱动最高支持 CUDA 12.8。CUDA 12.8 驱动可向前兼容 CUDA 12.4 的二进制。

**解决：** 降级到 CUDA 12.4 版本的 PyTorch

```bash
pip uninstall torch torchvision -y
pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu124
```

验证：

```
Torch: 2.5.1+cu124
CUDA available: True
Device: NVIDIA RTX5880-Ada-48Q
```

#### 3.2 transformers 与 torchao 版本冲突

**现象：** 导入模型时报错

```
  File ".../torchao/quantization/quant_primitives.py", line 191
    torch.int1: (-(2**0), 2**0 - 1),
AttributeError: module 'torch' has no attribute 'int1'
```

**排查：** `pip list` 看到 `transformers==4.57.6` 和 `torchao==0.17.0`。最新 transformers 的量化模块尝试导入 torchao，而 torchao 0.17.0 的 `torch.int1` 只在 PyTorch >= 2.6 中支持。降级即可。

**解决：**

```bash
pip install "transformers==4.47.0" "torchao==0.7.0"
```

#### 3.3 diffusers 自定义模块导入问题

**现象：** 导入 `diffusers.pipelines.cogvideo.pipeline_cogvideox_image2video` 失败

```
ImportError: cannot import name 'FLAX_WEIGHTS_NAME' from 'transformers.utils'
```

**根因：** `diffusers==0.32.1` 的旧版代码引用了 `transformers.utils.FLAX_WEIGHTS_NAME`，该常量在 transformers 5.x 中被移除。降级到 `transformers==4.47.0` 后修复。

#### 4.3 下载策略对比

**策略一：`snapshot_download`（不推荐）**

```python
from huggingface_hub import snapshot_download
snapshot_download(repo_id='THUDM/CogVideoX-5b-I2V', resume_download=True)
```

- 优点：一行命令下载全部
- 缺点：大文件时进度条容易卡住，进度停在 `0%` 但实际在下载；多个 `.incomplete` 文件并存时可能互相干扰

**策略二：`hf_hub_download` 逐文件下载（推荐）**

```python
from huggingface_hub import hf_hub_download
import time

files = [
    'transformer/diffusion_pytorch_model-00001-of-00003.safetensors',
    'transformer/diffusion_pytorch_model-00002-of-00003.safetensors',
    'text_encoder/model-00001-of-00002.safetensors',
    'text_encoder/model-00002-of-00002.safetensors',
]
for f in files:
    start = time.time()
    path = hf_hub_download(repo_id='THUDM/CogVideoX-5b-I2V',
                           filename=f, resume_download=True)
    elapsed = time.time() - start
    size = os.path.getsize(path)
    print(f'{f}: {size/1024/1024:.0f}MB in {elapsed:.1f}s')
```

每个文件独立下载、独立进度、断点续传更稳定。

## 关键教训

1. **云服务商的内网代理会劫持 DNS** — GitHub、HuggingFace 域名被解析到内网 IP `[内网代理IP]`。GitHub 改用 HTTPS 远程地址绕开，HuggingFace 直连速度尚可（5-10 MB/s）。

2. **服务器在日本 ≠ ClashX 日本节点快** — 直连通过 KDDI 网络可达 9.5 MB/s，走 ClashX 本地代理反而降到 1.3 MB/s。下载大模型时关掉代理更优。

3. **requirements.txt 的宽松版本号导致连锁不兼容**：
   - `torch>=2.5.1` → 装了 2.12.0+cu130，但系统驱动只支持 CUDA 12.8 → 需降级
   - `transformers>=4.45.2` → 装了 4.57.6，依赖 torchao 新特性 → torchao 又与旧版 torch 冲突 → 需降级两者
   - 教训：在固定环境部署时，应该用 `pip freeze > requirements-lock.txt` 锁定精确版本

4. **大文件下载策略**：
   - `snapshot_download` 容易在进度显示上卡住（实际在下载但显示 0%）
   - `hf_hub_download` 逐个下载更稳定，每个文件独立续传
   - 缓存目录的 `.incomplete` 文件是 HuggingFace Hub 的断点续传机制，不要手动删除

5. **小文件测速的误导性** — 小文件（几 KB）的 curl 测速结果受 TCP 握手和 TLS 协商主导，不能反映大文件的真实吞吐。使用 `Range` 头下载大块数据才能测出真实带宽。

### 建议

1. **锁定依赖版本** — 运行 `pip freeze > requirements-lock.txt` 记录当前可用的精确版本，避免后续重新部署时因版本更新导致不兼容。

2. **缓存 HuggingFace 模型** — 当前 `~/.cache/huggingface/hub/` 已缓存约 33GB 模型文件。如果需要清理磁盘，保留这两个目录即可避免重新下载：
   - `models--THUDM--CogVideoX-5b-I2V`
   - `models--anyeZHY--tesseract`

3. **多 seed 生成对比** — 推理脚本默认 `num_validation_videos=2`，可用不同 seed 对比结果差异，挑选效果最好的。

4. **监控显存** — 推理峰值 33GB、保留 41GB。如果同时跑其他任务注意不要超过 48GB 上限，否则 OOM 会直接 killed。
